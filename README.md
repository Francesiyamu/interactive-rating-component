# interactive-rating-component
Users often want to quickly provide feedback or rate a service, but many interfaces make this process confusing or unintuitive. This project provides a simple, interactive way for users to select a rating and immediately see a confirmation, making the feedback process straightforward and user-friendly.

### The challenge

Users should be able to:

- View the optimal layout for the app depending on their device's screen size
- See hover states for all interactive elements on the page
- Select and submit a number rating
- See the "Thank you" card state after submitting a rating

## My process

### Built with

- Semantic HTML5 markup
- CSS custom properties


### What I learned

Working on this project was a truly interesting challenge. Transforming a static HTML page into a fully functional interactive component felt like a significant milestone for me. Although I encountered some obstacles along the way, I didn’t let them discourage me. For me, the most important part wasn’t just completing the project, but understanding how each piece of code contributed to the overall build. At one point, I struggled with my JavaScript overriding my CSS styles, which was tricky to resolve, but I eventually figured it out. Now, I feel more confident in handling similar issues in the future. I learned a lot through trial and error, and each mistake became an opportunity to grow.


### Useful resources

- [Example resource 1](https://www.w3schools.com/jsref/prop_element_classlist.asp) - This helped me in adding CSS classes to my JS code. I really liked this pattern and will use it going forward.
- [Example resource 1](https://www.codecademy.com/journeys/front-end-engineer/paths/fecj-22-building-interactive-websites/tracks/fecj-22-building-interactive-websites/modules/wdcp-22-javascript-and-the-dom-cd08bde9-0117-4bed-8e92-afd54b041d2c/lessons/script-element/exercises/script-element-defer) - After going through the DOM syllabus on Codecademy, I learned that placing scripts just before the </body> tag is a valid approach—it ensures the HTML loads before the script runs. However, using the defer or async attributes in the <head> section is now preferred, as it offers more control and can improve page performance. Both methods are valid, but the newer approach is more flexible. I decided to incorporate this best practice into my project.
